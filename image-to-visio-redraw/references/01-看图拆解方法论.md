# 看图拆解方法论

把一张位图翻译成布局数据（JSON）的系统方法。这是整个流程里**唯一需要判断力**的环节，其余都是机械劳动。

---

## 一、读图时同步做三件事

不要"读完图 → 凭印象画"。读图的同一轮就要输出：

1. **区域清单**：这张图分成哪几块，各块边界在哪
2. **配色语义表**：每种颜色代表什么
3. **层级树**：谁包含谁

产出的三样东西直接决定后面写脚本的速度和准确度。

---

## 二、五类元素识别法

架构图 99% 的内容可归为五类。**逐类扫描，不要漏**。

| 类型 | 特征 | 画法 | 典型高度 |
|---|---|---|---|
| **① 层/带** | 横向满宽或占大半宽，有层名标签（"云""网""端"，或"应用层""平台层"） | 先画大底色块，内部再放子卡片 | 2.0 – 7.5 |
| **② 侧栏** | 左右两侧竖条，通常是"标准体系""安全保障""运维"这类贯穿性内容 | 竖长容器 + 若干纵向堆叠的项 | 高度 = 主体区高度 |
| **③ 卡片** | 有标题条 + 内容区，成组出现，同层内等宽 | 标题条（深色）+ 内容框（浅色） | 0.6 – 3.0 |
| **④ 网格项** | 卡片内部的小格子，通常 2×N 或 1×N 排列 | 等分列宽，逐格填充 | 0.3 – 0.6 |
| **⑤ 页眉/页脚/参与方** | 顶部场景条、底部参与方色块、角落图例 | 满宽或等分横排 | 0.35 – 0.7 |

### 扫描顺序（固定，避免遗漏）

```
顶 → 左 → 主 → 右 → 底
```

先扫最上面一条，再左竖栏，再中间主体（按行从上到下），再右竖栏，最后底部。**主体部分再按行细分**，行内从左到右。

## 三、拆解清单模板

读图时直接填这张表，填完就能写脚本：

```
【页面】尺寸 A2 横向 23.4 × 16.5

【顶部】
  标签："场景"，x=0.4 w=2.4
  4 项：载人出行 / 低空物流 / 公共服务 / 文化旅游   → 等分横排

【左栏】x=0.4 w=2.5（贯穿主体高度）
  标题："低空智联标准体系"
  3 项：数据与服务支撑类标准 / 智能网联航电类标准 / 基础设施类标准

【主体】x=3.1 w=17.2
  行1「云」高 3.0：3 张大卡
    - 运营管理系统（绿）2 行内容
    - 低空交通管理和服务系统（橙）3 行
    - 低空监管系统（绿）3 行
  行2「网」高 2.4：2 条满宽横条 + 4 个接入格
  行3「端」高 7.4：左右两半各 5 段
    - 左：低空载具及航电系统
    - 右：信息物理基础设施

【右栏】x=20.5 w=2.5
  标题："低空智联安全体系"
  3 项：装备体系安全 / 网络数据安全 / 电磁频谱安全

【底部】
  标签："参与方"
  5 项色块：制造方(黄) 交管服务方(橙) 监管方(紫) 运营方(绿) 基础设施服务方(蓝)

【配色语义】
  深蓝 → 层名/主标题    亮蓝 → 卡片标题条
  浅蓝 → 容器背景        白   → 内容区
  橙   → 交通管理类      绿   → 运营/监管类
  红   → 安全类
```

## 四、配色语义表（关键）

**颜色 = 角色**。动手前必须列出这张表，否则画出来"形似神不似"。

提取方法：
1. 扫一遍图里出现的所有颜色
2. 每种颜色找出它标注的同类元素
3. 归纳出语义

```
深蓝 #1F4E79  → 层名、主标题、页眉        （最高层级）
亮蓝 #2E75B6  → 卡片标题条                （次级）
浅蓝 #DDEBF7  → 容器/分区背景              （背景层）
极浅 #F0F7FD  → 大容器背景
白   #FFFFFF  → 内容区
─────────────
橙   #ED7D31  → 交通管理与服务
绿   #548235  → 运营 / 监管
紫   #7030A0  → 监管方
黄   #EDC240  → 制造方
红   #C0504D  → 安全体系 / 警示
```

**判定规则**：同色 = 同角色 / 同归属方。若某色只出现一次，多半是强调项，单独记录。

## 五、层级树

用缩进表达包含关系，直接对应代码里的"先画背景、后画子卡片"：

```
页面
├─ 顶部场景条
│   ├─ 标签"场景"
│   └─ 4 个场景卡
├─ 左竖栏（标准体系）
│   ├─ 标题
│   └─ 3 项
├─ 主体
│   ├─ 行1 云
│   │   ├─ 层名标签"云"
│   │   └─ 3 张大卡
│   │       ├─ 标题条
│   │       └─ 2~3 行 × 2 列 小格
│   ├─ 行2 网
│   │   ├─ 2 条满宽横条
│   │   └─ 4 个接入格
│   └─ 行3 端
│       ├─ 左半：5 段
│       └─ 右半：5 段
├─ 右竖栏（安全体系）
└─ 底部参与方：5 个色块
```

**代码对应**：越深的节点越晚画（叠在上层）。容器先画，子内容后画。

## 六、常见架构图的"套路"结构

认出套路能大幅加速拆解。以下是高频模式：

### 模式 A：云 / 网 / 端 三层（本 skill 示例）
```
顶部：应用场景（横排）
左栏：标准体系      右栏：安全/保障体系
主体：
  云 —— 应用系统（运营 / 交通管理 / 监管）
  网 —— 通信导航监视 + 数据交换网
  端 —— 载具航电 | 物理基础设施
底部：参与方（制造 / 服务 / 监管 / 运营 / 基础设施）
```

### 模式 B：分层架构（技术栈式）
```
顶部：用户/终端
 ├ 接入层
 ├ 应用层
 ├ 服务层（业务服务横向排列）
 ├ 数据层（数据库 / 缓存 / 对象存储）
 ├ 基础设施层（计算 / 网络 / 存储）
左栏：运维 / 监控    右栏：安全 / 标准
```

### 模式 C：边—端—云 协同（物联网/低空类）
```
云：中心平台（算力、存储、算法）
边：区域节点 / 汇聚节点
端：感知设备、终端、载具
横向：网络（5G/专网/卫星）
```

### 模式 D：业务流程闭环
```
申报 → 审批 → 执行 → 监控 → 归档
        ↑                    │
        └────── 异常处理 ──────┘
```

识别套路后，**先套模板骨架，再填具体文字**，比从零拆解快得多。

## 七、易错点

| 错误 | 后果 | 避免 |
|---|---|---|
| 只看颜色不看文字 | 结构对但内容错位 | 颜色只是辅助，**文字才是准绳** |
| 漏掉细小的角标/图例 | 图不完整 | 按"顶→左→主→右→底"顺序扫，不跳步 |
| 层级没表达 | 一堆平铺的框，看不出包含 | 容器加底色 + 子卡片留内边距 + 容器边框加粗 |
| 高度估小 | 文字溢出 | 宁可预留高一点；行高按 0.25/行 估 |
| 省略号没处理 | 内容缺失 | 按其归类补全，页脚注明 |
| 没发现原图错误 | 错误被复制 | 对可疑处（重复标签、明显分类错）**主动核对并告知用户** |

## 八、拆解后自检

回填这张表，全绿才动手写脚本：

- [ ] 区域清单覆盖了图的全部区域（顶/左/主/右/底）
- [ ] 配色语义表列全了所有出现的颜色
- [ ] 层级树表达了所有包含关系
- [ ] 每个卡片的**行数**和**列数**已确定
- [ ] 省略号/不完整处已决定如何补全
- [ ] 可疑标注已核对，必要时准备告知用户
- [ ] 估算了总形状数量（心里有数，通常 60–200）
